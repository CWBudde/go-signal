# Sticker Images and Sending Implementation Plan

Approved in chat on 2026-09-30. Implement the next new Later / on demand feature,
keeping earlier group/profile live checks open. No live mutations are authorized by default.

## Task 1: Shared contracts and isolation

Use the isolated `feat/stickers` worktree. Preserve the original checkout's modified
reference submodule. Add `Sticker.Image *Attachment`, `StickerReference` (hex PackID,
32-byte PackKey, uint32 StickerID), `StickerData` (Emoji, Image OutgoingAttachment),
`OutgoingSticker` (Reference, Emoji, Image UploadedAttachment), `Client.FetchSticker`,
and optional sticker fields on facade/application send requests.
`StickerReference.Check` validates the ID/key without exposing the key in errors.
`FetchSticker` needs no connection, respects cancellation and fails after Close.
Add `MessageMediaResult{Attachments []SavedAttachment, Sticker *SavedAttachment}`;
`App.SaveMessageMedia` and `Printer.SavedMessageMedia` consume it. Preserve existing
SaveAttachments/SavedMessage APIs and ordinary attachment numbering.

## Task 2: Backend and fake (exclusive internal/signal scope)

Write failing behavior tests before implementations. Fetch the manifest and selected
item from fixed Signal CDN paths using context-aware HTTP and bounded reads, rather
than the dependency's unsafe sticker helpers. Encrypted-response limits: 1 MiB
manifest, 100 MiB image. HKDF-SHA256: 32 zero salt bytes, info `Sticker Pack`, 64-byte
output; first 32 bytes AES key, rest HMAC key. Validate minimum length/alignment,
HMAC before AES-CBC decryption, and PKCS#7 padding. Return no unverified bytes.
Match manifest items by actual ID, reject missing/duplicate matching IDs, and handle
zero IDs. Preserve WebP, PNG/APNG and GIF bytes; use manifest MIME when supported,
otherwise sniff supported bytes if MIME is absent; reject unsupported MIME.
Never fetch the user-supplied URL. No dependency bumps, pack cache, install or fallback.

Add typed ErrInvalidSticker, ErrStickerNotFound, ErrStickerTooLarge errors.
Populate DataMessage.Sticker fields and reuse the same-client uploaded pointer under
Sticker.Data, without duplicating it under Attachments. Reject sticker combinations
with body, attachments, quote, mentions, reaction, delete or edit at facade validation.
Retain the received embedded pointer under Sticker.Image (no pack key retention needed),
with inbox round-trip/backward compatibility tests. Add configurable fake sticker data,
errors and observable fetched references; enforce validation/lifecycle/upload ownership.
All protobuf and backend types stay inside signal. Both backends and no-backend fake
build must compile. No shared files, commits, staging or repository-wide formatters.

## Task 3: Application (exclusive internal/app scope)

Write failing tests first. Parse only HTTPS signal.art /addstickers/ links with fragment
pack_id and pack_key; require exactly one of each, valid hex lengths, and no credentials
or non-default port. Optional unknown fragment fields need not be rejected. Return
ErrInvalidSticker without echoing raw links/keys. Validate sticker-only requests before
connecting. Resolve all recipients and enforce allowlists before fetching/uploading.
Fetch and upload exactly once for users/groups/self, then reuse existing timestamp and
partial-result machinery. Do not retry writes. Propagate fetch/upload failures without
sends. Maintain existing attachment/edit behavior.

SaveMessageMedia calls existing SaveAttachments plus a separate sticker download,
only when Sticker.Image exists. Use existing private/collision-safe writer with filename
`<timestamp>-sticker-<stickerID><extension>` (add .apng). Failures stay per item. Missing
image pointers remain metadata-only, including historical inbox entries.

## Task 4: Output (exclusive internal/output scope)

Write failing rendering tests first. Add optional nested sticker.image containing
ordinary attachment metadata, optional path/downloadError; no pack keys or Remote data.
Keep schema version 1. Plain output retains sticker marker and includes saved path/error
using existing control-character escaping. Existing metadata-only output is unchanged.
SavedMessageMedia handles independent regular/sticker results, preserving SavedMessage.

## Task 5: Controller integration, review and delivery

Add --sticker-pack and --sticker-id to send; both required together, explicit ID 0 valid.
Require sticker content as an alternative to message/stdin/attach; sticker alone rejects
any explicitly supplied message/stdin/attach/quote/quote-text/edit flags before client open.
Wire receive --download-attachments to SaveMessageMedia/SavedMessageMedia even for
sticker-only messages. Add focused command tests and goldens; update help, README,
docs/json.md and docs/dev.md with opt-in both-backend live procedure.

After shared interfaces stabilize, Tasks 2-4 run in parallel in disjoint packages; the
controller owns cmd/docs/PLAN.md and integration. Review every diff and run just fmt,
just check, just check-purego, and CGO_ENABLED=0 go test -count=1 ./.... Use temporary
caches and loopback-capable execution where the sandbox blocks fixture servers.
Keep implementation and live acceptance distinct in PLAN.md; preserve outstanding
group/profile checks and broader sticker/story/poll/pin parent. Commit and open a PR
after checks and independent review pass. Do not merge.
