# Pinned Messages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development or executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Send pin/unpin controls and inspect bounded retained observations offline.

**Architecture:** Reuse existing DataMessage sends and inbox storage. Shared typed contracts land first; signal, app and output package implementation can then proceed independently. CLI and integration belong to the controller.

**Tech Stack:** Go, Cobra, existing signalmeow protobuf, SQLite inbox and plain/JSON output.

**Spec:** docs/superpowers/specs/2026-09-30-pins-design.md

## Global Constraints

- No dependency/submodule bumps, database migrations, production calls or edits to reference/signal-cli.
- Target author is a non-nil ACI after resolution; target timestamp positive uint64. Pin duration is exactly positive uint32 seconds or Forever true. No pin protocol-version bump.
- Sends cover users, groups and self. All allowlist, fresh group attribute permission checks and author resolution finish before mutation; no automatic retries.
- Incoming pin/unpin is a typed control, not unread or automatically receipted. Malformed or mixed content is invalidPin.
- Retained list is offline, canonical chat references, default 1000 / maximum 10000 entries, one newest limit+1 query. Arrival order is inbox ID; finite expiry uses first retained receipt time for a duplicate event. Completeness always unknown; no max-three eviction projection.
- JSON schema version 1 stays additive. Tests use external _test packages and existing goldens.
- Workers edit only their assigned package, no plan edits, staging, commits, pushes, nested agents or repository-wide formatters. Controller owns history and shared records.

## Review Focus

1. Mixed pins with polls/stickers/reactions/edits must not silently discard a component (Task 2).
2. Group permission failure must prevent sends even when a direct target appears first; allowlists precede group fetch/author lookup (Task 3).
3. Redelivery must not renew a finite pin within the snapshot; same-identity conflicts must retain first valid observation (Task 3).
4. Missing history, expiry and deletes must not create an authoritative current-phone-state claim (Tasks 3–5).
5. Max uint32 duration and large uint64 target references must survive wire/output without overflow, signed coercion or hidden defaults (Tasks 1–5).
