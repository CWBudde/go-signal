# Group Polls Implementation Plan

> For agentic workers: use subagent-driven-development to implement the scoped tasks below. The user approved parallel work once shared interfaces are fixed.

**Goal:** Group poll creation, voting and closing; typed received poll events; results reconstructed from retained inbox observations.

**Architecture:** Keep the pinned signalmeow dependency and existing data-message transport. Poll creation is `Message.Poll`; votes and closes are envelope events. Results use one bounded local inbox query and no new database tables.

**Tech stack:** Go, Cobra, signalmeow, existing SQLite inbox and signaltest fake.

**Spec:** This document records the in-chat plan approved on 2026-09-30.

## Global constraints and approved design

- Commands: `polls create --group <id> --question <text> --option <text>... [--single-choice]`; `polls vote --group <id> --target <author>:<timestamp> --vote-count <number> (--option <index>... | --clear)`; `polls close --group <id> --target <timestamp>`; `polls show --group <id> --target <ACI>:<timestamp> [--scan-limit <number>]`.
- Exactly one canonical group ID per send command. Multiple choice defaults on. Zero-based selected indexes; explicit `--clear` withdraws. Explicit positive uint32 vote counter, increased by the caller each time; never infer from retained observations.
- Outbound creation: valid UTF-8, nonblank question, 2–10 nonblank options, each at most 100 UTF-16 code units. Preserve supplied text. Reject duplicate selected indexes and indexes outside 0–9. Reject missing/zero targets, mixed poll/message payloads, invalid group IDs and invalid CLI flags before connecting; CLI syntactic/payload validation precedes client opening.
- Typed facade payloads reuse group sending, allowlists, unique timestamps, message clones and partial-member results; no automatic retries. Creation sets required protocol version 8; vote and close follow the official builder without that field. Voting encodes binary 16-byte ACI.
- Receive poll creation/vote/close from every chat and own-device transcripts. Malformed controls become explicit unsupported `invalidPoll` events. Incoming creation allows up to 200 UTF-16 units for question and 100 for options, conservatively within the official client's receive limits; counters of zero are allowed inbound for compatibility. Reject multiple poll controls and combinations with reaction/delete/edit, attachments/sticker/quote/body/mentions in poll controls; creation with other content is also malformed. Do not panic or lose malformed events silently.
- Public JSON additions preserve schema version 1. Inbox codec remains compatible; no migration, dependency bump, new MCP tools or daemon routes. Received creations have ordinary message unread/read behavior; votes/closes are stored control events without automatic receipts.
- `show` never connects: canonical group ID, canonical ACI target only. Account lock is required; stop daemon/MCP first. Read latest chat inbox entries once with `Newest:true, Limit:scanLimit+1`, discard extra oldest entry; default limit 1000, maximum 10000. Report scanned count, entry bounds and truncation.
- Find creation by chat/author/timestamp first, then reduce controls in inbox ID order (including controls before creation). Valid duplicate creation is idempotent; conflicting creation is counted and first retained valid creation wins. Keep latest valid vote per voter by counter; equal counters retain first observation except own-device sync replaces with a later timestamp. Count conflicting equal-counter selections. Empty selection clears. With known creation, reject indexes beyond option count and multi-selection on single-choice polls. Retain structurally valid votes without creation but omit tally.
- Only creator closes; subsequent votes ignored after observed closure. Matching author's remote delete marks deleted, stops further vote reduction and suppresses totals. Never report authoritative open/complete. `Completeness` is always `unknown`; expose missing creation, ignored invalid observations and conflicts. Observation tally excludes withdrawn selections. Sort voter results by ACI for deterministic output.
- History is collected by existing MCP/daemon Inbox.Run, not ordinary `receive` or outgoing sends. Explain pruning and unavailable-history limitations. Live phone checks on both backends remain separately unchecked; no production Signal operations in this batch.
- Workers edit only their assigned package; no staging, commits, pushes, plan edits, repository-wide formatters or nested agents. Controller owns shared records, CLI, integration, reviews and shipping.

## Review focus

- Vote controls before creation and before/after closure must reduce without claiming global completeness.
- Sparse/malformed binary ACIs, missing scalar pointers and mixed payloads must yield unsupported content without panics.
- Invalid CLI input must beat unavailable-account errors, with no accidental sends.
- Pruned history and the bounded snapshot must not infer complete results or invent missing creation.
- Fake recording and protobuf construction must own independent mutable option/index slices.

## Execution decisions and limits

The approved in-chat plan authorizes implementation and PR shipping. Independent workers
used separate packages after the controller fixed the shared types; the controller owns
integration, shared records and Git history.

Inbound text bounds count UTF-16 units rather than grapheme clusters. This conservatively
rejects some unusually long emoji or combining-character text. A missing received vote
counter uses the protobuf-compatible zero default; outbound counters remain positive and
explicit. Repeated scalar `--vote-count` flags follow Cobra's last-value-wins behavior.

Malformed-content classification applies to events delivered to the facade. The pinned
signalmeow dependency intercepts group-call updates before forwarding their data message;
a malformed poll mixed with such an update cannot be classified as `invalidPoll` here.
Changing that dependency routing remains outside this batch. Unsupported events without a
target reference cannot be attributed to a particular poll's `ignoredInvalid` count.

- [ ] Record red CLI test proving poll command absence; establish data-only contract types in `internal/signal/poll.go`, `SendRequest`, `Message.Poll`, and `internal/app/poll_types.go`.

Facade contracts: `Poll{Question string, Options []string, AllowMultiple bool}`; `OutgoingPollVote{TargetAuthor Recipient, TargetTimestamp uint64, OptionIndexes []uint32, VoteCount uint32}`; `OutgoingPollClose{TargetTimestamp uint64}`. `SendRequest` gains `PollCreate *Poll`, `PollVote *OutgoingPollVote`, `PollClose *OutgoingPollClose`. `PollVote` event embeds `Envelope` and `OutgoingPollVote`; `PollClose` embeds `Envelope` and `OutgoingPollClose`. Backend owns validation methods `Poll.Check()`, `OutgoingPollVote.Check()`, `OutgoingPollClose.Check()` and sentinel `ErrInvalidPoll`.

Application contracts: `PollCreateRequest{GroupID,Question string, Options []string, SingleChoice bool}`; `PollVoteRequest{GroupID,Target string, OptionIndexes []uint32, VoteCount uint32, Clear bool}`; `PollCloseRequest{GroupID string, Target uint64}`. Methods `App.PollCreate`, `App.PollVote`, `App.PollClose` take context + request and return `(PollSendResult,error)`. `PollSendResult` embeds SendResult with `Operation string`, `Poll *signal.Poll`, `TargetAuthor signal.Recipient`, `TargetTimestamp uint64`, `OptionIndexes []uint32`, `VoteCount uint32`. Operations are `create`, `vote`, `close`; creator target identity uses own ACI and creation send timestamp.

Show contracts: `PollShowRequest{GroupID,Target string, ScanLimit int}` and `App.PollShow(context.Context,PollShowRequest) (PollState,error)`. `PollState` has `Chat signal.Chat`, `Author signal.Recipient`, `Timestamp uint64`, `Creation *signal.Poll`, `Votes []PollStateVote`, `Tally []int`, `ClosureObserved bool`, `ClosedAt uint64`, `Deleted bool`, `Completeness string`, `Scanned int`, `FirstEntryID,LastEntryID int64`, `Truncated bool`, `IgnoredInvalid,Conflicts int`. `PollStateVote{Voter signal.Recipient, OptionIndexes []uint32, VoteCount uint32, Timestamp uint64}`. Missing creation represented by nil Creation; nil Tally means unavailable.
